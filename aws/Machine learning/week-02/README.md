# Week 02 — Planning a Machine Learning Project

## Course Completed

**Planning a Machine Learning Project**

## My Understanding

In this course, I learned that an ML problem needs to be **clear and quantifiable** so that the value provided by the model's predictions can be measured against specific business objectives and success criteria.

I learned that machine learning is most appropriate when a problem requires **complex logic, scalability, personalization, or responsiveness**. However, ML may not be the best solution when the problem can be solved effectively using traditional algorithms, does not require adaptation to new data, requires 100% deterministic accuracy, or requires complete interpretability.

Another major lesson was that the **data needs to be ready before building an ML solution**. Data readiness depends on factors such as the quality, quantity, diversity, and complexity of the available data.

After discovering or collecting the data, it needs to be properly:

1. Cleansed
2. Validated
3. Transformed
4. Stored

The data should also be easily accessible, relevant to the problem, and handled in a way that respects privacy.

## Planning an ML Project

I learned that an example ML project can be planned across approximately **12 weeks**, with different stages taking different amounts of time:

| Stage                        | Approximate Duration |
| ---------------------------- | -------------------: |
| Problem Definition           |               1 week |
| Data Exploration             |               1 week |
| Data Preparation             |               1 week |
| Modeling, Training & Testing |              3 weeks |
| Evaluation                   |               1 week |
| Deployment                   |            3–4 weeks |

This showed me that developing an ML solution involves much more than simply training a model.

## Questions to Consider Before Deployment

Before deploying a model, I learned that we should consider questions such as:

* What is the likely computational cost of generating predictions with the model?
* How quickly does the data change?
* How significant are the changes needed to deploy the model?
* Does the model's performance actually meet the business need?

## Key Takeaway

My major takeaway from this course is that **machine learning should be driven by a clearly defined business problem and measurable objectives**.

Having a model that performs well technically is not enough. The data must be suitable, the solution must be practical to operate, and the model must ultimately provide value toward the original business goal.

This helped me understand that successful machine learning is not simply about building accurate models—it is about building the **right solution for the right problem**.
